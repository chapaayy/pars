# VPN Newsroom

Личная админка для редакции Telegram-канала о VPN. Собирает новые сообщения **разрешённых** Telegram-каналов и RSS, объединяет близкие события, оценивает релевантность через бесплатный/выбранный AI API, формирует черновики и отправляет их только после подтверждения администратора.

## Запуск на VPS

Требования: Ubuntu/Debian VPS (x86_64/ARM64), 80/443 TCP и 443 UDP открыты, DNS A/AAAA-запись домена указывает на VPS. Docker Engine и Compose при необходимости автоматически ставятся из официального APT-репозитория (для этого запускай `sudo ./install.sh`). При запуске нужен доступ к Docker Hub/PyPI и Let’s Encrypt.

```bash
# Скачай архив или склонируй репозиторий проекта, затем:
# На чистом Ubuntu/Debian VPS в одной команде:
sudo bash -c 'set -e; apt-get update -qq; apt-get install -y -qq git ca-certificates; git clone https://github.com/chapaayy/pars.git /opt/pars; cd /opt/pars; printf "DOMAIN=pars.gowayot.com\n" > .env; chmod 600 .env; bash install.sh' 
```

Открой `https://pars.gowayot.com`, укажи код из логов, логин и пароль администратора. Затем зайди в **Настройки**, вставь ключ AI (Groq или Gemini), токен Telegram-бота, укажи @имя своего канала. Бот должен иметь право публиковать в целевом канале.

Если домен не указывает на VPS, сертификат HTTPS не выпустится. На других дистрибутивах Linux нужно заранее поставить Docker Engine и compose plugin по [официальной инструкции](https://docs.docker.com/engine/install/).

### Обновление и обслуживание

```bash
sudo /opt/pars/update.sh  # git pull + перестроит и перезапустит приложение, сохранив volumes
sudo /opt/pars/logs.sh    # логи веб-приложения и код первого запуска
```

Для других команд `docker compose` необходимо в текущем shell установить секрет `export DB_PASSWORD="$(cat secrets/db_password)"`, если Compose требует раскрытия `DATABASE_URL`. Фоновые логи: `docker compose logs --tail=150 worker`.

Данные хранятся в Docker volumes `db_data`, `app_data`, `caddy_data`. **Не выполняй `docker compose down -v` без резервной копии!** Резервное копирование базы:

```bash
export DB_PASSWORD="$(cat secrets/db_password)"
docker compose exec -T db pg_dump -U newsroom -d newsroom -Fc > newsroom.backup
```

## Откуда приходят новости

- **RSS/Atom:** добавляешь URL, фоновый обработчик проверяет новые записи раз в 15 минут (настраивается). Для первого подключения берутся последние 30 записей, но старше четырёх дней материалы не добавляются. Дубли в одном источнике игнорируются.
- **Telegram:** Bot API получает только **новые** `channel_post` от каналов, в которые бота добавили с разрешения владельцев. В поле источника указывай `@channel` или точный цифровой ID (`-100...`). Бот не может получить старую историю чужого канала. Если канал скрыт, используй цифровой ID из его `chat`.
- **Вручную:** можно вставить пост или статью и ссылку в «Ленте». Удобно для пересланных новостей.

Важно: у одного бота может быть только один активный `getUpdates` consumer; не запускай этот же токен параллельно в другом боте/сервисе. Если у бота настроен webhook, его нужно отключить перед использованием polling. Telegram может не присылать новые сообщения от канала, если у бота нет нужных прав.

## AI-анализ

- Для каждого нового сообщения модель возвращает оценку полезности, доверия к источнику, новизны, объяснение, краткое резюме и название события.
- Рейтинг темы рассчитывается по релевантности (35%), оценке достоверности (25%), новизне (20%) и свежести (20%). Это **редакторские оценки, а не фактчекинг**.
- Похожие события из нескольких источников объединяются эвристикой сравнения названий в окне 5 дней. ИИ не гарантирует идеальное объединение и не проверяет факты в интернете.
- Генерация черновика отдельно использует все сообщения темы; пост редактируется вручную до публикации.

AI-сервис подключается в настройках. Начальная модель Groq: `openai/gpt-oss-20b`; для Gemini при смене провайдера автоматически предлагается `gemini-3.1-flash-lite`. Доступность и бесплатные квоты зависят от аккаунта и могут меняться. Можно указать другую модель.

**Автоматической публикации нет.** Кнопка публикации доступна только вошедшему администратору, после дополнительного подтверждения. После сбоя соединения статус «Проверить отправку» специально не перезапускается автоматически, потому что Telegram мог получить сообщение до таймаута.

### Безопасность и ограничения v1

Первый запуск требует одноразового кода, доступного только в логах VPS. Админ-пароль хешируется через scrypt, сессии хранятся в БД, чувствительные токены шифруются локальным ключом в volume. Веб-формы проверяют CSRF; внешние XML-запросы ограничены; пользовательские каналы/ключи не раскрываются наружу.

Этот проект — начальная рабочая версия, а не высоконагруженная система. Нет мультиаккаунтов, автоматического фактчекинга, веб-поиска и сбора истории каналов. Для крупного production перед следующими изменениями нужны миграции схемы БД, мониторинг, регулярные резервные копии и проверка обновлений зависимостей.

### Домен и установка из GitHub

Исходники: https://github.com/chapaayy/pars. В `.env.example` задан `DOMAIN=pars.gowayot.com`, а команда выше также явно записывает домен в локальный `.env`. `.env` и `secrets/` исключены из git. Перед запуском проверь DNS A-запись `pars.gowayot.com` на IP VPS и что TCP 80/443 свободны.
